IDENTIFIED IMPROVEMENTS
=======================

1. STRUCTURED ERROR TYPES (Priority: HIGH, Effort: MEDIUM)
   Status: Missing
   Issue: All errors are generic error type. Callers can't distinguish timeout 
          vs quota exhaustion vs missing executable.
   Impact: Prevents fine-grained error handling and type-safe routing
   File: /Users/arielspivakovsky/src/flip/flip2/internal/llm/process.go:180-204
   
   Recommendation: ADOPT
   Create ExecutionError type with Code field for specific error types:
   - "timeout" → implement retry with backoff
   - "quota_exhausted" → fallback to different backend
   - "not_found" → fail immediately, check installation
   - "execution_error" → log and retry

2. RETRY WITH EXPONENTIAL BACKOFF (Priority: HIGH, Effort: MEDIUM)
   Status: Missing
   Issue: No automatic retry for transient failures. Fire-and-forget on error.
   Impact: Transient failures (network glitch, temporary rate limit) cause 
           cascading failures instead of recovering
   Files: /Users/arielspivakovsky/src/flip/flip2/internal/llm/process.go

   Recommendation: ADAPT
   Add ExecuteWithRetry() with:
   - Max 2-3 attempts for timeout/rate-limit errors
   - Exponential backoff (1.5x) with jitter to prevent thundering herd
   - No retry for permanent errors (missing executable, bad arguments)

3. CONTEXT CLEANUP WITH DEFER (Priority: HIGH, Effort: LOW)
   Status: Partial - missing in some paths
   Issue: cancel() only called in error paths. Success path relies on timeout.
          Goroutine cleanup deferred at deepest level (risky if panic).
   Impact: Resource leaks on success path. Goroutine leaks possible.
   File: /Users/arielspivakovsky/src/flip/flip2/internal/llm/process.go:244-269

   Recommendation: ADOPT
   Add defer cancel() immediately after context.WithTimeout():
   
   execCtx, cancel := context.WithTimeout(ctx, timeout)
   defer cancel()  // <-- Add this line
   
   This is Go idiom and ensures cleanup on all code paths.

4. STREAMING WITH TYPE-SAFE EVENT HANDLERS (Priority: MEDIUM, Effort: MEDIUM)
   Status: Partial - raw channel exposed
   Issue: Callers receive <-chan StreamChunk and must manually manage:
          - Check Done flag
          - Accumulate text
          - Extract tokens from final chunk
          - Handle errors mixed into channel
   Impact: Error-prone caller code. No help from compiler.
   File: /Users/arielspivakovsky/src/flip/flip2/internal/llm/process.go:266-323

   Recommendation: ADAPT
   Create AccumulatingStream wrapper with .Consume(ctx, handlers) method:
   
   stream.Consume(ctx, &StreamHandler{
       OnText: func(text string) error { fmt.Print(text); return nil },
       OnComplete: func(content string) error { ... },
       OnError: func(err error) { ... },
   })

5. CIRCUIT BREAKER PATTERN (Priority: HIGH, Effort: MEDIUM)
   Status: Partial - quota-only implementation
   Issue: Only quota tracked. Other failures don't cause circuit to open.
          No "fast fail" for repeatedly failing backends.
   Impact: Cascading failures when backend repeatedly fails. Wasted API calls.
           User waits for timeout instead of getting immediate error.
   File: /Users/arielspivakovsky/src/flip/flip2/internal/llm/process.go:334-373

   Recommendation: ADOPT
   Enhance CheckQuota() to become full CircuitBreaker:
   - Track Closed (ok) → Open (reject calls) → HalfOpen (testing recovery)
   - Open after N consecutive failures (e.g., 3)
   - Auto-recovery attempt after ResetTimeout (e.g., 30 seconds)
   - Metrics: circuit_breaker_state{backend,state}

6. MIDDLEWARE/INTERCEPTOR PATTERN (Priority: MEDIUM, Effort: HIGH)
   Status: Missing
   Issue: Metrics logic (execCount, lastExec) mixed in Execute().
          Adding new concerns (logging, tracing, auth) requires modifying Execute().
   Impact: Difficult to test individual concerns. Concerns entangled.
   File: /Users/arielspivakovsky/src/flip/flip2/internal/llm/process.go:152-228

   Recommendation: ADAPT
   Create Interceptor interface and InterceptingBackend wrapper:
   
   type Interceptor interface {
       BeforeExecute(ctx, prompt, opts) error
       AfterExecute(ctx, resp, err) error
   }
   
   Usage:
   backend := &InterceptingBackend{
       backend: NewClaudeBackend(),
       interceptors: []Interceptor{
           NewMetricsInterceptor(),
           NewLoggingInterceptor(),
           NewTracingInterceptor(),
       },
   }

7. STRUCTURED LOGGING WITH CONTEXT (Priority: MEDIUM, Effort: LOW)
   Status: Partial - Go ok, Python needs work
   Issue: Python scripts use print() instead of logging.
          Go uses slog but no context propagation.
   Impact: Logs are not queryable. Hard to trace requests through system.
   Files: /Users/arielspivakovsky/src/flip/flip2/scripts/signal_monitor.py
          /Users/arielspivakovsky/src/flip/flip2/internal/executor/executor.go

   Recommendation: ADOPT
   - Go: Add context to every log call
     logger.ErrorCtx(ctx, "failed", "error", err, "duration_ms", ms)
   - Python: Use logging module with context variables
     logger.info("started", extra={"agent_id": self.agent_id})
