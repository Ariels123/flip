================================================================================
TECHNICAL DETAILS
================================================================================

SCORING DIMENSIONS (0-10 scale):

1. Correctness: Does it work correctly? Does it meet requirements?
2. Efficiency: Is it performant? Optimized complexity?
3. Maintainability: Is it clean, readable, maintainable?
4. Security: Are there security vulnerabilities?

Overall Score = (Correctness + Efficiency + Maintainability + Security) / 4

PASS/FAIL DETERMINATION:

Default Threshold: 6.0/10

IF overall_score >= 6.0 THEN
  status = "pass"          → Accept result
ELSE
  status = "fail"          → Queue for retry

Optional: status = "needs_review" for manual human review

GO STRUCT (simplified):

type VibeScoreCard struct {
    TaskID                      string
    Correctness, Efficiency,    float64  // 0-10 scores
    Maintainability, Security
    OverallScore                float64

    Evaluator      string      // "claude", "gemini", etc.
    EvaluatorModel string      // "claude-opus-4-5", etc.
    EvaluatedAt    time.Time

    CorrectnessFeedback    string
    EfficiencyFeedback     string
    MaintainabilityFeedback string
    SecurityFeedback       string
    SummaryFeedback        string

    ImprovementSuggestions []string
    Status                 Status  // pass/fail/needs_review
    QualityThreshold       float64 // default: 6.0

    RetryCount      int    // 0 = first attempt, N = Nth retry
    PreviousScoreID string // Links to prior evaluation

    Metadata map[string]interface{}
}

DATABASE INDEXES (optimized):

- task_id → Find all evaluations for a task
- evaluator → Agent performance statistics
- evaluated_at → Time-range queries
- overall_score → Sort by quality
- status → Find pass/fail results
- task_id + evaluated_at → Latest eval per task

Query performance: <5ms indexed lookups

================================================================================
KEY DESIGN DECISIONS
================================================================================

1. Four Dimensions
   ✓ Covers code quality holistically
   ✓ Each independently measurable
   ✓ Balanced technical + maintainability

2. 0-10 Scale
   ✓ Familiar to humans (like grades)
   ✓ Allows fine-grained scoring (8.5 vs 8.0)
   ✓ Easy to communicate

3. Overall = Simple Average
   ✓ Treats all dimensions equally
   ✓ Easy to understand
   ✓ Can be weighted later if needed

4. Default Threshold: 6.0
   ✓ 60% = passing grade baseline
   ✓ Filters clearly inadequate work
   ✓ Allows room for improvement
   ✓ Per-task customization supported

5. Retry Tracking
   ✓ Learn from failures
   ✓ Enables continuous improvement
   ✓ Maintains full history

6. Three-State Status
   ✓ pass = accept
   ✓ fail = retry
   ✓ needs_review = gray area
